“ Preguntas Frecuentes y Troubleshooting

¿Ca³mo reinicio el servicio MariaDB si falla una restauracia³n?

sudo systemctl restart mariadb
Para verificar estado: sudo systemctl status mariadb

¿Qua© hacer si el archivo .sql es muy grande (> 1GB)?

Usar compresia³n gzip: mysqldump -u user -p BD | gzip > backup.sql.gz
Reduce tamaa±o ~70%. Para restaurar: gunzip -c backup.sql.gz | mysql -u user -p BD

¿Error "Permission denied" al leer archivo PostgreSQL?

Archivo propiedad de postgres, permisos 600. Soluciones:
1) sudo chown $USER:$USER archivo.sql
2) sudo chmod 644 archivo.sql
3) Restaurar como root: sudo psql -U postgres < respaldo.sql

¿Ca³mo verifico que un respaldo es va¡lido ANTES de necesitarlo?

Restaurar a BD de prueba:
MariaDB: mysql -u root -p test_db < respaldo.sql
PostgreSQL: createdb test_db && psql test_db < respaldo.sql
Luego: SELECT COUNT(*) FROM tabla; para verificar datos

¿Cada cua¡nto debo hacer respaldos?

Filosofa­a: RPO (Recovery Point Objective) define el intervalo. Recomendaciones:
- Datos cra­ticos: diario (o cada 4 horas)
- Datos normales: semanal
- Datos hista³ricos: mensual
Automatizar con cron: 0 2 * * * mysqldump ... | gzip > /backups/daily_$(date +\%Y\%m\%d).sql.gz

¿Ca³mo restauro solo una tabla especa­fica sin restaurar todo?

Extraer SQL de una tabla del respaldo:
sed -n '/CREATE TABLE.*tabla_x/,/CREATE TABLE/p' respaldo.sql > tabla_x.sql
O mejor: mysqldump -u user -p --tables tabla_x > tabla_x.sql

¿Qua© diferencia hay entre respaldo la³gico y fa­sico?

La³gico (este documento): SQL portable, lento, legible, puedo restaurar parciales
Fa­sico: Copiar archivos de datos (/var/lib/mysql), ra¡pido, opaco, restauracia³n completa
Usar la³gico para: migraciones, versionamiento. Usar fa­sico para: RPO muy bajo, BDs > 100GB
