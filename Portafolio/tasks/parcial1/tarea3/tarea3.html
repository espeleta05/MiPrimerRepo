🎯 Objetivo

Instalar y configurar PostgreSQL en servidor Linux (CentOS/RHEL), crear esquemas avanzados con roles, permisos, vistas, funciones PL/pgSQL, y Window Functions. Aprender diferencias clave vs. MySQL y administración empresarial.

💡 Conceptos Clave

PostgreSQL - ORDBMS

Object-Relational Database Management System. Más potente que MySQL: soporte objetos, tipos complejos, arrays, JSON, extensibilidad. PostgreSQL es Open Source y empresarial (AWS, Google usan).

PostgreSQL Docs ↗

Instalación en Linux

En CentOS/RHEL: sudo yum install postgresql postgresql-server postgresql-contrib. Inicializar con initdb, iniciar servicio, crear superusuario. Configurar pg_hba.conf para acceso remoto.

PostgreSQL RHEL ↗

Roles y Permisos

CREATE ROLE con LOGIN, PASSWORD, SUPERUSER flags. GRANT/REVOKE en databases, schemas, tablas. Distinción entre roles (usuarios y grupos). Mejor control de acceso que MySQL.

Gestión de Usuarios ↗

Vistas (Views)

Tablas virtuales basadas en SELECTs. Vistas materializadas MATERIALIZED VIEW almacenan datos (necesitan refresh). Útiles para seguridad y reutilización de lógica.

PostgreSQL Views ↗

Window Functions

Análisis de datos: ROW_NUMBER(), RANK(), LAG(), LEAD(), SUM() OVER(). Permiten cálculos sobre "ventana" de filas sin GROUP BY. ROW_NUMBER() para paginación, LAG() para comparar con fila anterior.

Window Functions ↗

psql - CLI

Cliente interactivo de PostgreSQL. Comandos especiales: \d (describe tabla), \l (listar bases), \du (usuarios), \df (funciones). Scripting y automatización. Más poderoso que mysql CLI.

psql Reference ↗

🔧 Pasos de Implementación

Paso 1: Instalación y Configuración Inicial

sudo yum install postgresql postgresql-server postgresql-contrib
sudo postgresql-setup initdb
sudo systemctl start postgresql
sudo systemctl enable postgresql

sudo -u postgres psql
CREATE SUPERUSER postgres WITH PASSWORD 'secure_pwd';

Paso 2: Crear Roles y Permisos

CREATE ROLE app_user LOGIN PASSWORD 'app_pass' CREATEDB;
CREATE ROLE analyst LOGIN PASSWORD 'analyst_pass';
CREATE ROLE admin_group NOLOGIN;

GRANT admin_group TO app_user;
GRANT USAGE ON SCHEMA public TO analyst;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO analyst;

Paso 3: Diseño de Esquema Relacional

CREATE TABLE clientes (
    id SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    telefono VARCHAR(15),
    fecha_registro TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    activo BOOLEAN DEFAULT true
);

CREATE TABLE pedidos (
    id SERIAL PRIMARY KEY,
    cliente_id INT NOT NULL REFERENCES clientes(id),
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    total DECIMAL(12,2),
    estado VARCHAR(20) CHECK (estado IN ('pendiente', 'enviado', 'entregado'))
);

CREATE TABLE detalles_pedido (
    id SERIAL PRIMARY KEY,
    pedido_id INT NOT NULL REFERENCES pedidos(id) ON DELETE CASCADE,
    producto_id INT NOT NULL,
    cantidad INT CHECK (cantidad > 0),
    precio_unitario DECIMAL(10,2)
);

Paso 4: Crear Índices y Restricciones

CREATE INDEX idx_cliente_email ON clientes(email);
CREATE INDEX idx_pedido_cliente ON pedidos(cliente_id);
CREATE INDEX idx_pedido_fecha ON pedidos(fecha DESC);

ALTER TABLE clientes ADD CONSTRAINT email_check CHECK (email LIKE '%@%');
ALTER TABLE pedidos ADD CONSTRAINT total_check CHECK (total >= 0);

Paso 5: Vistas y Vistas Materializadas

-- Vista simple para reportes
CREATE VIEW reporte_ventas AS
SELECT c.nombre, COUNT(p.id) as total_pedidos,
       SUM(p.total) as monto_total, AVG(p.total) as promedio
FROM clientes c
LEFT JOIN pedidos p ON c.id = p.cliente_id
GROUP BY c.id, c.nombre
ORDER BY monto_total DESC;

-- Vista materializada (para consultas costosas)
CREATE MATERIALIZED VIEW top_clientes AS
SELECT c.nombre, SUM(p.total) as lifetime_value
FROM clientes c
JOIN pedidos p ON c.id = p.cliente_id
GROUP BY c.id, c.nombre
ORDER BY lifetime_value DESC
LIMIT 10;

-- Refrescar vista materializada
REFRESH MATERIALIZED VIEW top_clientes;

Paso 6: Window Functions para Análisis

-- Ranking de clientes por monto gastado
SELECT c.nombre,
       ROW_NUMBER() OVER (ORDER BY SUM(p.total) DESC) as ranking,
       SUM(p.total) as total_gastado
FROM clientes c
LEFT JOIN pedidos p ON c.id = p.cliente_id
GROUP BY c.id, c.nombre;

-- Comparar pedido actual con anterior del mismo cliente
SELECT cliente_id, id, total,
       LAG(total) OVER (PARTITION BY cliente_id ORDER BY fecha) as pedido_anterior,
       total - LAG(total) OVER (PARTITION BY cliente_id ORDER BY fecha) as diferencia
FROM pedidos
ORDER BY cliente_id, fecha;

-- Percentiles y cuartiles
SELECT total,
       PERCENT_RANK() OVER (ORDER BY total) * 100 as percentil
FROM pedidos;

❓ FAQ sobre PostgreSQL

¿PostgreSQL vs. MySQL? ¿Cuál debería usar?

PostgreSQL: Más robusto, tipos complejos, Window Functions, JSON nativo, extensible, mejor para datos complejos.

MySQL: Más simple, más rápido en lectura pura, mejor compatibilidad hosted (AWS RDS es más caro en PostgreSQL).

Decisión: Startups rápidas → MySQL. Aplicaciones complejas → PostgreSQL.

¿Cómo conectarse remotamente a PostgreSQL?

Modificar /var/lib/pgsql/data/postgresql.conf: listen_addresses = '*'

Modificar pg_hba.conf: host all all 0.0.0.0/0 md5

sudo systemctl restart postgresql

psql -h 192.168.1.100 -U usuario -d database

¿Cómo asignar permisos granulares?

GRANT SELECT ON tabla1, tabla2 TO role_x; (solo lectura)

GRANT INSERT, UPDATE, DELETE ON tabla1 TO role_y; (completo menos CREATE)

REVOKE DELETE ON tabla1 FROM role_y; (remover permiso)

¿Window Functions vs. GROUP BY?

GROUP BY: Agrupa → reducción de filas. Resultado: una fila por grupo.

Window Functions: Sin agrupar → mantiene todas las filas. Agregación "local" en ventana.

Ejemplo: GROUP BY para totales, Window Functions para ranking con detalle.

¿Cuál es la diferencia entre View normal y MATERIALIZED?

View: Query guardada, recalcula cada acceso. Siempre actualizado, pero lento si es complejo.

Materialized View: Almacena resultado. Rápido, pero puede estar obsoleto hasta REFRESH.

Uso: VIEW para datos que cambian poco, MATERIALIZED para inteligencia/reportes.

¿Cómo optimizar query lenta en PostgreSQL?

EXPLAIN ANALYZE SELECT ... muestra plan y tiempo real.

Buscar "Seq Scan" en salida → necesita índice.

CREATE INDEX idx_col ON tabla(col) WHERE col IS NOT NULL; (índice parcial).

¿Soporte de JSON en PostgreSQL?

Tipos JSONB (binario, más rápido) y JSON (texto). Operadores: ->, ->>, @>, <@

SELECT data->>'email' FROM users WHERE data @> '{"active":true}';

Permite híbrido relacional + documental sin cambiar DBMS.

📋 Conclusiones

🎓 Aprendizajes

PostgreSQL es más potente que MySQL. Window Functions transforman análisis de datos. Vistas materializadas son herramienta crítica para performance. Roles y permisos en PostgreSQL más granulares que MySQL.

⚡ Desafíos

Sintaxis de Window Functions complicada inicialmente. Entender plan de ejecución (EXPLAIN) requiere práctica. Configurar pg_hba.conf para seguridad sin ser restrictivo.

🚀 Mejoras

Aprender PL/pgSQL para triggers y funciones. Explorar particionamiento para big tables. Integrar con PostGIS para datos geoespaciales. Usar pgAdmin para admin visual.

Q1: "¿Por qué usar Window Functions si GROUP BY es más simple?"
R: GROUP BY reduce filas, Window Functions mantienen detalle. Si necesito ranking, totales corridos, o comparaciones fila a fila → Windows. GROUP BY si solo quiero agregado final.
Q2: "¿Cómo refrescar Materialized View automáticamente?"
R: Con cron job o trigger. PostgreSQL no soporta REFRESH automático como MySQL's REFRESH. Alternativa: Logical Replication o CONCURRENTLY para evitar locks.
